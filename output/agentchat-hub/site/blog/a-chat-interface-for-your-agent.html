Building with agents

Your agent works. Give someone a way to use it.

An agent can be useful long before it has its own polished frontend. AgentChat Hub lets you connect a compatible A2A endpoint and talk to it from a desktop or phone.

Practical guide · Illustrative workflow, not a customer case study

The problem: an endpoint is not a comfortable place to ask a question

Imagine you built an agent that answers questions about your project’s documentation. You can send it a request and read its response. But showing it to someone else means explaining a command, sharing a script, or starting another project just to build a chat screen.

You want to learn whether the agent answers useful questions. Building its client is becoming a separate job.

Use AgentChat Hub as the client

If your agent exposes an A2A interface that AgentChat Hub supports, you can add it by URL. The app reads its agent card, displays the information it provides, and gives you a conversation interface.

  1. Run your agent at an endpoint reachable from the device you will use.
  2. In AgentChat Hub, choose Add Agent → A2A Agent.
  3. Paste the agent URL and fetch its agent card.
  4. Review the agent’s details, add it, and open a conversation.
  5. Ask a question that exercises the job you built it for.
“Based on the project documentation you can access, explain the release process. Point out any steps that are unclear or undocumented.”

In this example, the agent needs its own access to those documents. Connecting it to AgentChat Hub does not automatically give it a knowledge base, web access, or new abilities. The app is the place you interact with the capabilities the agent already has.

What this resolves

You can try the agent in a desktop or phone chat interface without first building that interface yourself. When you have several compatible agents, you can keep them in one roster and group them by purpose.

A teammate can connect to the same endpoint if they have the necessary access. Their conversations are their own; this does not create a shared team inbox or shared chat history.

Hosted anywhere still means compatible and reachable

Your agent can live on your machine, a private server, or a hosting provider. Its location is not the deciding factor. Its protocol, supported version, authentication requirements, and network reachability determine whether the connection works.

A2A uses agent cards to describe agents and their capabilities. See the official agent discovery documentation. Protocol versions can differ, so verify compatibility with the app before sharing an endpoint.

Keep access controls appropriate to what the agent can do. AgentChat Hub does not host your agent or collect your conversations. The agent’s operator controls how requests are processed and whether the server retains data.

A couple of questions

Can I paste any chatbot website URL?+

No. The URL must lead to a compatible A2A agent endpoint, not just an ordinary website or chat page.

Does this give my agent new tools or knowledge?+

No. The agent supplies its own capabilities. Connecting it creates a way to interact with those capabilities; it does not automatically add documents or tools.
